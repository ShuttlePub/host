# follow — open questions

> [../../clarifications/open.md](../../clarifications/open.md) も参照。

## Open questions blocking this feature

1. **フォロー UI の配置場所**
   - フォロー入力欄は「自分のアカウント」の詳細画面のみに表示するか、それとも任意のアカウント詳細画面に表示するか。
   - 自分以外のアカウントで表示する場合、権限のないユーザーに対してはどう制御するか（UI 側で非表示にするか、Emumet 側の 403 を待つか）。

2. **対象入力の補助**
   - `@user@domain` 形式の入力欄で、先頭の `@` を自動で補完/取り除くか、あるいはユーザーが入力した値をそのまま送信するか。
   - actor URL と nanoid の区別はフロントエンドで行うか、BFF または Emumet 側に任せるか。

3. **承認制フォローの UX**
   - `approved: false` が返された場合、フロントエンドで「フォローリクエストを送信しました」と表示するか、それとも「承認待ち」ステータスを継続的に表示するか。
   - 承認待ちのフォロー状態をどこで保持/表示するか（一覧機能との関係）。

4. **同一アカウントの複数フォロー禁止**
   - 既にフォロー済みの対象を再度フォローした場合、Emumet は重複を許容するか、エラーを返すか。
   - フロントエンドで重複チェックを行う必要があるか。

5. **Mock 実装の `approved` 値**
   - mock では常に `approved: true` を返すか、target 形式によって `true`/`false` を切り替えるか（テストカバレッジに影響）。
