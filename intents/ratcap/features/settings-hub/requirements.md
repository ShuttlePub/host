# settings-hub — requirements

> [overview.md](overview.md) を参照。

## Functional requirements

1. **設定ハブレイアウトの再構成**
   - `src/App/View/Settings.purs` の view を設定ハブに置き換える。
   - ページタイトル「Settings」に加え、各設定カテゴリをセクション/カード形式で配置する。

2. **アカウント設定セクション**
   - セクションタイトル「アカウント設定」を表示する。
   - 現在保持しているアカウント一覧（`Model.accounts`）を表示する。未取得の場合は「アカウント一覧へ」リンクを表示する。
   - 各アカウントカードにはアカウント名と「詳細を開く」リンクを表示し、クリックで `/accounts/{id}` へ `Navigate` する。
   - 各アカウントカードから危険領域（アカウント削除）へ直接遷移するリンクも併記する（実際の削除 UI は `AccountDetail.purs` 側で実装）。

3. **セッション情報セクション**
   - セクションタイトル「セッション情報」を表示する。
   - 現在ログイン中のユーザー名（`Model.session.username`）を表示する。
   - ログアウトボタンを配置し、`Logout` メッセージを発行する。
   - セッション未取得の場合は「ログインしていません」と表示する。

4. **ブロック/ミュート管理セクション（将来機能）**
   - セクションタイトル「ブロック/ミュート（準備中）」を表示する。
   - 簡潔な説明文と「今後の機能です」placeholder テキストを表示する。
   - 実際のブロック/ミュートリスト取得・編集は本 slice では実装しない。

5. **表示設定セクション**
   - 既存のテーマ/形状選択 UI（`colorSection`, `shapeSection`）を本セクションに移動する。
   - 今後の拡張（フォントサイズ、言語選択など）に備えた placeholder 領域を確保する。

6. **ナビゲーション・リンク**
   - 各リンクは `App.View.Link` モジュールの `link` または `App.Message.Navigate` を使用する。
   - セッションがない場合はアカウント設定セクションを非表示またはダミー表示にする。

## Non-functional requirements

- **SSR + ハイドレーション**: Settings ページは SSR 時にサーバー側でレンダリングされる。`Model.session` は SSR 時に `Nothing` のため、セッション情報セクションは「ログインしていません」と表示してよい。クライアントマウント後の `CheckSession` で更新される。
- **認可**: 設定ページ自体は未認証でも閲覧可能とする（`isProtectedRoute` は現状すべて `/login` 以外を保護しているため、実際には認証必須）。未認証時はセッション情報セクションが「ログインしていません」と表示されるだけで、ログインへの導線を表示する。
- **アクセシビリティ**: 各セクションには `h2` 見出しを付与し、カードのリンクには明確なラベルを持たせる。
- **テスト**: 現状 UI テストが少ないため、手動 QA で確認する。`spago build` が成功することを最低限の自動検証とする。
- **将来の拡張**: ブロック/ミュート、アカウント削除専用ページ、表示設定の詳細は本 slice では実装せず、ナビゲーションと placeholder のみ整備する。
