# settings-hub — packets

> [../../packets/](../../packets/) に domain-level packet がある場合は参照。

## Execution units

### Packet 1: Settings ハブレイアウト実装
- **対象ファイル**: `src/App/View/Settings.purs`
- **作業内容**:
  1. 既存の `view` を設定ハブレイアウトに書き換える。
  2. 「アカウント設定」「セッション情報」「ブロック/ミュート（準備中）」「表示設定」セクションを作成する。
  3. テーマ/形状選択 UI を「表示設定」セクションに移動する。
  4. `App.View.Link` を使って各アカウント詳細ページと危険領域への導線を貼る。
  5. セッション情報セクションに `Model.session` の username とログアウトボタンを配置する。
  6. `spago build` でコンパイルエラーを解消する。
- **完了条件**: `spago build` が成功し、ブラウザで `/settings` を開いた際にハブレイアウトが表示される。

### Packet 2: Model/Message 調整とナビゲーション接続
- **対象ファイル**: `src/App/Model.purs`, `src/App/Message.purs`, `src/App/View.purs`, `src/Client/Update.purs`（または一元 Update ファイル）
- **作業内容**:
  1. 必要に応じて `Model` に設定ハブ用の一時状態を追加する（初回 slice では不要な可能性も高い）。
  2. 設定ハブからアカウント詳細への遷移が既存の `Navigate` メッセージで動作するよう確認する。
  3. ログアウトボタンから `Logout` メッセージが発行されるよう接続する。
  4. サーバー側 SSR (`Server.purs`) で `Settings` ページが正しくレンダリングされることを確認する。
- **完了条件**: 設定ハブの各リンクが動作し、ログアウトボタンを押すとログイン画面へ遷移する。

### Packet 3: 手動 QA + 将来機能 placeholder 確認
- **対象ファイル**: （なし、主に手動検証）
- **作業内容**:
  1. mock モードで `/settings` を開き、各セクションが表示されることを確認する。
  2. ログイン済み状態で username が表示されることを確認する。
  3. アカウント一覧が表示されている場合、各アカウントカードから詳細画面へ遷移できることを確認する。
  4. ブロック/ミュートセクションの placeholder テキストが表示されることを確認する。
  5. 表示設定セクションのテーマ/形状カードが表示されることを確認する。
- **完了条件**: 手動 QA で設定ハブの基本的な動作を確認する。
