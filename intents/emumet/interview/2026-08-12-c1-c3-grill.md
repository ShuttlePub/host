## Q0: ShuttlePub 本体の扱い(C2/C3 の設計前提)

**Answer**: C2/C3 の設計確定は早計。一旦おいておく(deferred)。

**帰結**: C2(post-relay)と C3(shuttlepub-link)は、連携先 ShuttlePub 本体が
実在しない(受け口・認証ともにゼロ、本体リポジトリ停止中)状況では、IF だけを
確定しても手戻りリスクが高い。両スレッドは「ShuttlePub 本体実装の構想が立った
時点で再 grill する」を再開条件とする deferred とする。
C1(media-upload)は本体非依存で完結するため、本セッションで grill を継続する。

**影響**:
- packets/backlog.md の post-relay / shuttlepub-link は Deferred 維持
  (再開条件を明記する更新を別途行う)
- post-relay の open-questions(転送プロトコル/サービス間認証/再送方針/署名 API
  の扱い)と shuttlepub-link の open-questions(認証方式/multiplicity/登録主体)は
  いずれも本体設計前提のため、本セッションでは深掘りしない
