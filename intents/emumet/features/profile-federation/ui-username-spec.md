## B: Profile ユーザー名の入力（D08）

配置: 新しい Route は作らない。既存の `Accounts`（Home）、`AccountNew`、`AccountDetail` に手を入れる。形式は `^[a-z0-9][a-z0-9._-]{0,63}$`、変更はできない。

1. **@ 表記に使う名前**
   - 一覧カードと詳細ヘッダの @ 表記は、Profile のユーザー名（`@name@host`）に統一する。
   - Account 名は詳細の「Account Info」にだけ出す。
2. **ユーザー名の初期値**: 空欄にする。Account 名からの提案や自動コピーはしない。
3. **「変更できない」の確認**
   - 新規作成: ［作成］を押すと確認の段に切り替わる。
     - タイトルは「この ID で作成しますか？」。
     - 中身は完成形の ID（例 `@alice@emumet.example`）と「後から変更できません。」の 1 行だけ。
     - ボタンは［戻る］と［作成］。
   - 既存 Profile への設定: 同じ形で、タイトルは「このユーザー名にしますか？」、ボタンは［戻る］と［設定］。
   - チェックボックスでの確認は使わない。
   - 入力欄の下には「後から変更できません」を出さない（確認と重複するため）。
4. **入力欄と検証**
   - 入力欄: ラベル「ユーザー名」と (?) ヘルプ。入力欄の前に `@`、後ろに `@host` を付ける（mobile は後ろの `@host` を省く）。
   - 状態表示: 入力欄の下に 1 行だけ出す（「確認しています」「✓ 利用できます」「✕ ＜理由＞」）。
   - 形式と予約語: 入力中にその場で検証する。
   - 重複: 入力が止まってからサーバーに問い合わせ、送信時にもサーバーで再判定する。
   - エラーの文言:
     - 形式違反: 「先頭は a〜z か 0〜9、以降は a〜z、0〜9、. _ - が使えます」
     - 長すぎ: 「長すぎます」
     - 予約語・使用済み: 「利用できません」
   - 大文字は自動で小文字に変換せず、形式違反のエラーにする（「小文字にする」ボタンも出さない）。
   - ［作成］［設定］は、ユーザー名が「利用できます」になるまで押せない（新規作成では Account 名も必須）。
5. **ユーザー名が未設定の既存 Profile への導線**
   - 一覧カードの @ 表記の代わりに「ユーザー名未設定」と出す。
   - 詳細ページの先頭に 1 行の注意「⚠ ユーザー名が未設定です［設定する］」を出す（閉じられない）。
   - 設定は、Profile 欄の「ユーザー名」行の［設定］（または注意の［設定する］）からモーダルで 1 回だけ行う。モーダルはユーザー名欄と［キャンセル］［設定］のあと、3 の確認に進む。
   - 設定を強制はしない（ログイン時のモーダルや、他の操作を止めることはしない）。
   - 設定後は Profile 欄に `@name` と 🔒（変更不可）を出す。
6. **代わりの候補**: 予約語や使用済みのときも、代わりの候補は出さない。
7. **Account の作成**
   - Home（Accounts 一覧）の右上の「＋」からモーダルで作成する。モーダルの中身は Account 名、ユーザー名、Bot、［キャンセル］［作成］。確認（3）は同じモーダルの中で次の段に切り替わる。
   - 既存の Route `AccountNew`（/accounts/new）を消すか、モーダルを開いた一覧への入口として残すかは、実装時に別途決める。
