v2 の方針: Misskey の新規登録フォームにならい、ユーザー名欄は「ラベル＋(?)、@ と @host を入力欄に付ける、下に状態 1 行」だけにした（Misskey は「後から変更できません」も常に出すが、ここでは確認方式 C のときだけ出す）。X の設定画面（「ユーザー名 ＞」の行を押して入力 1 つの画面へ）にならい、既存 Profile での設定は Profile 欄の行からモーダルを開く形にした。配置は v1 と同じ（AccountNew / AccountDetail / Accounts に追加、Route は増やさない）。

1@ 表示に Account 名とユーザー名のどちらを使うか

  1. @ 表記はユーザー名に統一し、Account 名は Account Info にだけ出す。
  2. 現状どおり @Account 名を見出しにする。
  3. 両方を並べる。
推奨: 1（v1 は一覧カードとヘッダにも「Account: work」を補助表示していたが、v2 では Account Info だけに残した）

2ユーザー名の初期値

  1. 空欄。Account 名が使える形式なら「Account 名から入力」の提案ボタンを出す。
  2. Account 名を自動でコピーする。
  3. 空欄で提案なし。
推奨: 3 — v1 から変更（v1 の推奨は 1）。Misskey にも X にも提案ボタンはなく、入力欄が 1 つ増えるだけなので省いた。

3「変更できない」の確認方式

  1. A: 確定時にモーダルを出す（完成形の ID と「後から変更できません」の 1 行だけ）。
  2. B: フォーム内の必須チェックボックス。
  3. C: 入力欄の下に「後から変更できません」と出すだけ（Misskey 型）。
推奨: A（変更なし。ただしモーダルの説明文は削り、ID と 1 行だけにした。入力欄の下の「後から変更できません」は C のときだけ表示し、A・B ではモーダル／チェックボックスと重複するので出さない。C はモック上部の「確認方式」で比較できる）

4検証のタイミングと大文字の扱い

  1. 入力中に検証し、重複は入力が止まってから確認する。大文字はエラーにする（自動変換しない）。
  2. 大文字は自動で小文字に変換する。
  3. 送信時にまとめて検証する。
推奨: 1 — v1 から一部変更: v1 にあった「小文字にする →」ボタンは削除し、エラーは「a〜z、0〜9、. _ - が使えます」の 1 行にまとめた（Misskey と同じ粒度）。

5ユーザー名未設定の既存 Profile への導線の強さ

  1. 一覧に「ユーザー名未設定」と表示し、詳細の先頭に 1 行の注意＋［設定する］を出す。設定は Profile 欄の行からモーダルで行う。
  2. ログイン直後にモーダルで設定を求める。
  3. 設定するまで他の操作をできなくする。
推奨: 1 — v1 から一部変更: v1 は詳細の先頭に説明文付きのカードを置き、その中で入力させていた。v2 では注意を 1 行（Misskey の管理画面の注意と同じ形）にし、入力はモーダルに移した。

6予約語・使用済みのときに代わりの候補を出すか

  1. 使える候補を 2〜3 個出し、押すと入力される。
  2. 出さない。
推奨: 2 — v1 から変更（v1 の推奨は「使用済みのときだけ 1」）。Misskey は「利用できません」と出すだけで、候補なしでも困らないため。

7Account 作成を別ページにするか、一覧の「＋」から開くモーダルにするか

場所: Home（Accounts 一覧）の右上の作成ボタン。現行は「+ New Account」で別ページ（/accounts/new）に移る。モック上部の「Account 作成の形」で切り替え、一覧から作成までを試せる。

  1. 現行どおり別ページ（New Account）。
  2. 一覧右上の「＋」→ モーダル（Account 名・ユーザー名・Bot・［作成］）。確認は同じモーダルの中で次の段に切り替わる。
推奨: 2 — 入力は 3 つだけで一覧から離れる必要がなく、D08 で指示された「＋→モーダル」ともそろう。実装では Route の AccountNew を消すか、モーダルを開いた一覧への入口として残すかを別に決める。

仮置き: ホスト名 emumet.example と予約語・使用済みの名前は仮／mobile では入力欄の「@emumet.example」を省略／既存画面の見出し（Accounts / New Account / Profile 等）は英語のまま。
