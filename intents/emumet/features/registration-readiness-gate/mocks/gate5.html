画面 A（v5）: 一般登録の準備ゲート管理 — UI 論点

v5 の変更（文言のみ）: 「対策」を「保護」に統一（「BOT 対策」も「BOT 保護」）。状態「開放中（防御低下）」を廃止し、片方の保護が応答しなくても状態チップは「開放中」（どの保護かは各行の「応答なし」で分かる）。Webhook の送る通知から「防御低下」を外した（応答なしは「障害」で届く）。「無対策で」「上書き」をやめ、状態は「強制開放中」、操作は［強制開放…］／確認「強制開放しますか？」［強制開放］／警告帯「⚠ 強制開放中［解除］」／［強制開放を解除］にそろえた。

v4 の変更: 「通知」を管理画面のタブから外し、nav のベル（未読数つき）にした。ベルを押すと通知パネルが開く（desktop はベルの下に幅 360px、mobile は画面幅）。管理のタブは「一般登録」「Webhook」の 2 つ。nav の「管理」に付けていた未読数はベルへ移した。Misskey も通知は管理画面の中ではなく、ナビのベル（未読の印つき）から開く。

v3 の変更: 余白・行の高さだけを詰めた（構成と文言は v2 と同じ）。基準は Misskey の CSS（ページ余白 24px／狭い画面 12px、ブロック間 16px／500px 以下 10px、折りたたみ見出し 9px 12px、ボタン 7px 14px、入力欄 高さ 36px）。値は Tailwind の 4px 刻み（10px は 2.5）に丸めた。

v2 の方針: Misskey のコントロールパネルにならい、画面には「状態と操作」だけを置き、仕組み（自動再開／手動再開の違い、適用範囲、強制開放の挙動）は (?) からヘルプページへ回す。配置: nav の「管理」→ タブ「一般登録」「Webhook」（v4）。Route は AdminRegistration / AdminWebhook。通知はベルのパネルなので Route は不要（論点 1 で案 3 を選ぶ場合だけ AdminNotifications を足す）。成功・警告色はトークンの追加が必要。

1通知ベルの位置と開き方

v4 で「通知はタブではなくベルで分ける」ことは反映済み。残るのは位置と開き方（位置はモック上部の「ベルの位置」で切り替えられる）。

  1. nav 右側（「管理」の隣）にベル。押すとその場にパネルが開く。
  2. 左端（ロゴの前）にベル。開き方は 1 と同じ。
  3. ベルは通知ページ（/admin/notifications）へのリンクにし、パネルは出さない（Misskey の通知ページ型）。
推奨: 1 — 「管理」の隣にあると管理者向けの通知だと分かりやすく、どのページからでも一覧を見て戻れる。通知は管理者にしか届かないので、ベル自体も管理者にだけ出す。将来一般利用者向けの通知を入れる場合は同じベルにまとめる前提。v3 から変更: v3 の推奨（nav の「管理」に未読数＋管理内の「通知」タブ）は、ユーザーの指摘で取りやめた。

2状態の見せ方

  1. 状態チップと、その状態で押せる操作だけを出す。挙動の説明は (?) からヘルプへ。
  2. 状態チップと全操作を並べ、押せないものは無効表示。
  3. 状態遷移図を常に表示。
推奨: 1 — v1 から変更: v1 は「次に起きること」の説明文を状態カードに書いていたが、v2 では削除した。自動で再開する一時停止には［再開］を出さず、自動停止には［再開］を出すので、ボタンの有無で違いが伝わる。

3強制開放の確認の強さ

  1. 確認モーダル（影響 1 行＋必須チェック＋危険色ボタン）。
  2. 1 に加えて、サーバー名などの文字列入力を求める。
  3. 1 に加えて、再認証を求める。
推奨: 1 — v1 から変更: v1 にあったリスク 5 項目の箇条書きと理由入力欄を削除し、「解除するまで自動停止しません」の 1 行だけにした。

4強制開放中の警告帯の範囲と形

  1. 管理画面の枠に常に表示し、閉じられない。［解除］付き。
  2. 管理者には全ページに表示。
  3. 1 だが閉じられる。
推奨: 1（変更なし。帯の文言は 1 行に短縮）

5メール認証・BOT 保護の設定をこの画面で変えるか

  1. 状態表示と［再検証］だけ。設定方法は (?) からヘルプへ。
  2. この画面で編集できる（Misskey は管理画面でプロバイダとキーを編集する）。
  3. 有効・無効の切り替えだけ画面で行う。
推奨: 1（変更なし。各カードの「設定は Ory で…手順を見る」の行は、見出しの (?) 1 つに集約）

6Webhook の登録と表示

  1. 「+」→モーダル（URL・シークレット・送る通知）で登録する。一覧には URL の一部を伏せて表示。失敗した配送だけを並べ、1 件ずつ再試行できる。
  2. URL を全文表示し、全配送の履歴を出す。
  3. URL も再入力でしか変えられない書き込み専用にする。
推奨: 1 — v1 から変更: v1 は設定フォームを画面に常に置き、成功分を含む配送履歴を全部出していた。v2 では「+」→モーダルにし、配送履歴は失敗分だけにした（Misskey の Webhook 設定も一覧＋作成ボタンの形）。

7「招待と既存利用者の Account 追加は対象外」を画面に出すか

場所: 管理 →「一般登録」タブの一番下（「保護」一覧の下）。v1 はここに「この設定が適用される範囲」カードを置き、v2 で外した。モック上部の「適用範囲の表示」で 3 案を切り替えられる（「なし」のときは、論点ピン表示中だけ黄色い点線で位置を示す）。

  1. 出さない。「一般登録」の (?) からヘルプへ。
  2. 1 行だけ出す（「対象: 新規の一般登録のみ。招待・既存利用者の Account 追加は対象外」）。
  3. v1 のカード（見出し＋3 項目＋補足）を出す。
推奨: 1 — 画面は状態と操作だけにする v2 の方針に合わせる。「招待も止まるのでは」と管理者が迷うことが多そうなら 2。

仮置き: 強制開放を解除したとき条件を満たしていなければ「停止中」に戻す／一時停止中は［強制開放…］を出さない／［再検証］で一時障害が復旧するのはモック上の演出／アクセントボタンの文字色はコントラストのため暗色。
