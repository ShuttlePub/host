## A: 一般登録の準備ゲート管理（D15、管理者のみ）

配置: nav に「管理」を置き、管理画面のタブは「一般登録」「Webhook」の 2 つ。Route は `AdminRegistration` と `AdminWebhook` を追加する。

1. **通知ベル**
   - 位置と表示: nav の「管理」の右隣に、管理者にだけベルを出す。未読があればベルに件数を出す。
   - 開き方: ベルを押すと、その場に通知パネルが開く（desktop はベルの下に幅 360px、mobile は画面幅）。パネルの外を押すか Esc で閉じる。
   - パネルの中身: 見出し「通知」と［すべて既読にする］、その下に通知の行（未読の印、種別の色、タイトル、時刻）を並べる。行を押すとその通知だけ既読になる。
   - 既読: 管理者ごとに記録する。
   - その他: 通知は管理画面のタブには置かないので、通知用の Route（AdminNotifications）は作らない。将来、一般利用者向けの通知もこのベルにまとめる前提。
2. **状態の見せ方**
   - 「一般登録」パネルには、状態チップと、その状態で押せる操作だけを出す。説明文は置かず、(?) からヘルプへ。
   - 状態と操作の組み合わせは次のとおり（「条件」は、メール認証か BOT 保護の少なくとも一方が準備済みであること）。
     - 未開放（グレー）: ［開放］。
     - 開放中（緑）: ［停止］。片方の保護が応答しない場合も、チップは「開放中」のまま。どの保護が応答しないかは、「保護」一覧の該当する行のチップ（応答なし）で示す。
     - 一時停止中（黄。準備済みの保護がすべて応答なし）: ［停止］のみ。［再開］は出さない（復旧すると自動で再開するため）。
     - 自動停止（赤。設定の喪失による停止）: ［再開］。保護が復旧しても、管理者が手動で再開する。
     - 停止中（グレー。管理者による停止）: ［再開］。
     - 強制開放中（赤）: ［強制開放を解除］。
   - 条件を満たさないとき、未開放・自動停止・停止中の［開放］［再開］は無効にする。あわせて、短い表示「保護が未準備」と［強制開放…］（論点 3）を添える。
   - ［停止］は確認を挟まず、すぐに停止する（管理者による停止になる）。
3. **強制開放の確認**
   - 確認モーダルの中身は次の 3 つだけにする。
     - タイトル「強制開放しますか？」
     - 影響の 1 行「解除するまで自動停止しません。」
     - 必須のチェック「リスクを理解しました」
   - ボタンは［キャンセル］と、危険色の［強制開放］。［強制開放］はチェックするまで押せない。
   - 理由の入力欄、文字列の入力、再認証は求めない。
4. **強制開放中の警告帯**
   - 強制開放中は、管理画面の枠（nav の直下）に 1 行の警告帯「⚠ 強制開放中［解除］」を常に出す。閉じられない。
   - 解除したとき（警告帯の［解除］、または一般登録パネルの［強制開放を解除］）の動き:
     - 条件を満たしている場合: 確認なしで解除し、通常の判定に戻す（開放のまま）。
     - 条件を満たしていない場合: 確認「強制開放を解除しますか？ 一般登録は停止します。」（［キャンセル］［解除］）を出し、解除後は停止中（管理者による停止）にする。
5. **保護（メール認証・BOT 保護）の表示**
   - この画面では状態を見せることと［再検証］だけを行う。設定の変更は Ory 側で行い、見出し「保護」の (?) からヘルプへ案内する。
   - 各行に出すもの: 名前、状態チップ（未設定／設定エラー／未確認／準備済み／応答なし）、短い理由（例: 「サイトキーが不正」「タイムアウト」）、最終確認時刻、［再検証］。
   - 未設定の行は、時刻と［再検証］を出さない。
6. **Webhook**
   - 登録: 「Webhook」タブの見出し「送信先」の右にある「＋」から、モーダルで登録する。モーダルの中身は次のとおり。
     - URL、シークレット、送る通知（障害・復旧・自動停止・強制開放）。保護が応答しなくなったことは「障害」で届く。
     - ボタンは［キャンセル］と［保存］。編集時は［削除］も出す。
   - 一覧の行: URL は一部を伏せて表示し（例 `hooks.example.net/••••/a8f2`）、状態チップ（正常／配送失敗）、［テスト］、［編集］を並べる。シークレットは表示しない。
   - 配送失敗: 失敗があるときだけ「配送失敗」の一覧（時刻・通知名・［再試行］）を出し、1 件ずつ再試行できる。成功した配送の履歴は出さない。失敗があるときはタブに●を付ける。
7. **適用範囲の表示**
   - 「招待と既存利用者の Account 追加は対象外」は画面に出さず、「一般登録」の (?) からヘルプへ回す。
   - v1 で「一般登録」タブの一番下に置いていたカードは使わない。

### 確定文言（リード承認 `question-f24eeb05650d956c943da656275847ac`）

- 通知タイトル:
  - 「一般登録を一時停止しました」
  - 「{保護名}が復旧しました」
  - 「{保護名}が応答しません」
  - 「一般登録を自動停止しました」
  - 「保護の適用が復旧しました」
  - 「強制開放しました」
  - 「強制開放を解除しました」
  - （E15x の通知カテゴリとの対応: 障害 = 一時停止・応答しません、復旧 = 復旧しました・保護の適用が復旧しました、自動停止 = 自動停止しました、強制開放 = 強制開放しました・解除しました）
- 操作失敗の 1 行表示: 「他の管理者が変更しました」「接続できません［再試行］」「権限がありません」「この状態では操作できません」
- 短い表示: 「保護が未適用」
- 保護の短い理由: 「シークレットが不正」「SMTP 認証失敗」「タイムアウト」「接続失敗」 等
- 通知パネルの末尾: ［さらに読み込む］
- 時刻の表示: 当日は `HH:MM`、それ以外は `MM/DD`
- 操作者名は通知に出さない

### ［再検証］は入力なし（`d15-q05`）

- ［再検証］は入力を求めない。初回も検証 API の応答で準備済みの状態になる。

### Webhook の API 前提（ユーザー決定 `question-433de6d63c710adbcaa304b4ba7d1ba6`、unit E15x `registration-webhook-endpoint-management`）

- 6「Webhook」の登録・編集・削除は、Emumet に追加する送信先 CRUD API（E15x、[Emumet#97](https://github.com/ShuttlePub/Emumet/issues/97)）を前提とする。F15 の Webhook タブは E15x の OpenAPI 公開後に接続する（shuttlepub-frontends#31 は open のまま）。
- 「送る通知」の 4 つは API のカテゴリ識別子 `outage`（障害）/ `recovery`（復旧）/ `auto_stop`（自動停止）/ `override`（強制開放）に対応する。
- URL は API が部分マスクの形でしか返さない（全 URL・path は返さない）。したがって **編集モーダルの URL・シークレット欄は空で開き、入力したときだけ置き換える**（空のまま保存 = 変更しない）。
- 配送失敗の一覧は cursor ページングで古い失敗にも到達でき、1 件ずつ再試行できる（［さらに読み込む］で続きを読む）。
