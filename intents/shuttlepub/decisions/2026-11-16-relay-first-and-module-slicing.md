## KJ法で得たまとまり (2026-11-16 時点)

`/api/v1` の 15 操作、`dev` (f12933b) のコード、D12-D19 から書き出した責務を
まとめたもの。module 名は実行単位の設計で決める。

| まとまり | 入れた責務 |
|---|---|
| A. 連合の受け口と配送 | Follow の受理と Accept、フォロワー (購読者) の保持、Announce の転送、配送と再試行、署名の検証と付与、リモート actor の取得 |
| B. 投稿 | Note の作成、返信、引用、リポスト |
| C. 反応 | いいね、絵文字リアクション、クイックリアクション設定 |
| D. 読み出し | タイムライン、Note の取得、検索、通知、リアクション状態 |
| E. 表示と操作の制御 | ドメイン制御による拒否、隠し表示と reveal、操作の可否 |
| F. 記録と実行の基盤 | イベントの保存、プロジェクションの実行、起動と設定、マイグレーション |
| G. 外部の身元 | Profile の識別、認証、自身の actor と鍵 |

A〜E は各層で同じ名前の module として縦に揃える。F は driver と server の起動部分、
G は kernel の口として置く。現在の `kernel::entities` / `kernel::interface`
(種類別の分け方) は、まとまりの module へ移す。
