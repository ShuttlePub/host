## 1. 設定の一覧・追加と主導線

- **1-1** 一覧はミュートとブロックを 1 つにまとめ、「すべて／ミュート／ブロック」で絞り込む。この絞り込みは「ドメイン」「アカウント」の両タブに置く。行に種別の切替ボタンは置かない。直接追加はドメイン一覧右上の「+」→ モーダル（ドメイン入力欄と［ミュート］［ブロック］ボタンのみ）。主導線は投稿・プロフィールの「…」メニューの「〈ドメイン〉をミュート／〈ドメイン〉をブロック」で、ミュートは確認なしで即時実行し「元に戻す」付きトースト、ブロックは 2-1〜2-3 の確認を出す。ミュート・ブロックの違いや仕組みの説明は画面に置かずヘルプへ。
- **1-2** 設定「ミュート・ブロック」の中を「アカウント」「ドメイン」のタブ（サブページ）に分ける。
- **1-3** 画面内に対象 Profile の表示は置かず、ナビの Profile 切替に任せる（設定は現在の Profile にだけ適用）。
- **1-4** 入力は URL・@user@・パス・ポート・大文字・末尾ドット・国際化ドメインを機械的に正規化する。www. の除去などの推測補正はしない。ワイルドカード・IP アドレス・自サーバーは短いエラー。
- **1-5** 直接入力（「+」のモーダル）では入力中のプレビューは出さない。［ミュート］［ブロック］を押した時点で確認モーダルを出し、正規化後のドメインと「このドメインのみが対象」を示す。対象外の例は出さない。
- **1-6** 一覧の行は、ドメインタブではドメインと追加日、アカウントタブではアイコン・名前・acct と、行末の［ミュート解除］または［ブロック解除］ボタンだけ。種別のラベル（バッジ）は置かず、ボタンの文言と文字色で種別を兼ねる（［ミュート解除］は青系 theme-temp-low、［ブロック解除］は赤系 theme-error。塗りではなく文字色のみ、枠は通常の border）。状態の説明文は出さない。［ミュート解除］は即時（元に戻す付きトースト）、［ブロック解除］は 2-5 の確認を出す。ドメイン・アカウント両タブで同じ形。
  - `target_actor` が pending／unavailable の行も、取れている範囲で名前を `display_name` → `preferred_username` → `acct` → actor URL の順で表示し、アイコンは代替アイコンにする。状態文は出さず、解除は常に可能にする（`d08-q20-relation-row-unresolved-display`）。
  - 他サーバーのアイコン画像は `d09-q06-remote-media-fetch-path` に従う。安全な自サーバー経由の配信経路がなければ代替アイコンを使い、ブラウザから外部サーバーへ直接読み込まない。安全な配信（プロキシ）は別 unit とする。

## 2. ブロック／解除の確認

- **2-1** ブロック確認では、解除されるフォロー中・フォロワーの人数を出し、折りたたみで対象アカウント一覧を見せる。関係が 0 件なら出さない。
- **2-2** 解除される関係が 1 件以上のときだけ「元に戻らない」ことの確認チェックを必須にする。
- **2-3** ブロック確認に［代わりにミュート］を置く。押した後のトーストは「〈ドメイン〉をミュートしました」だけ。
- **2-4** ダイアログにはそれ以外の説明（相手への通知、残るもの、範囲、効果の列挙など）を置かない。ヘルプへ。
- **2-5** ブロック解除の確認は、タイトルと「できるようになること」1 文だけ。ボタンは［キャンセル］［ミュートに変更］［ブロック解除］。

## 3. 直接 URL・プロフィールで開いたとき

- **3-1** 対象ドメインの投稿を URL で直接開くと、最初は隠し、種別（ブロック中／ミュート中）とドメインだけを示す。投稿者名・本文は出さない。
- **3-2** ［この投稿だけ表示］はそのページを開いている間だけ有効。再読込・再訪で再び隠す。表示中は［隠す］で戻せる。設定が変わらない旨などの説明文は置かない。
- **3-3** 表示後もブロック中は操作ボタンを鍵付きにし、押すと 4-1 のシートを出す。ミュート中は通常どおり操作できる。
- **3-4** 第三者が対象ドメインの投稿を引用した投稿も全体を同じ方式で隠し、引用元ドメインを示す。引用者への操作は制限しない。
  - API 側の対応（2026-11-14、[ShuttlePub PR #25](https://github.com/ShuttlePub/ShuttlePub/pull/25)で S8 を拡張）: 直接表示の hidden に理由判別子 `cause`（`direct`／`quote`）を持たせ、`quote` のとき引用元ドメインと種別（ミュート／ブロック）を返す。［この投稿だけ表示］（reveal）1 回で引用元も含めて全体を表示する。引用元の CW・削除・閲覧権は reveal 後も制限されたまま。引用先が削除済み・閲覧不可の場合は引用元ドメインを出さない（引用が理由の隠しにしない）。タイムライン・通知・検索は 5-1 のまま引用ごと出さない。
- **3-5** スレッド内の対象ドメインの返信は「非表示の返信 n 件」に折りたたみ、展開後も 1 件ずつ［表示］する。
- **3-6** ミュート中・ブロック中のドメインの人のプロフィールを開くと、名前・自己紹介と「ブロック中のドメイン／ミュート中のドメイン」バッジは表示し、投稿一覧は最初は隠す。隠し方は 3-1 と同じ（種別とドメインだけ）で、［投稿を表示］で表示する。表示はそのページを開いている間だけで、［隠す］で戻せる。表示後もブロック中は操作ボタンを鍵付きにする（3-3）。説明文は置かない。

## 4. ブロック中の相手への操作

- **4-1** 操作ボタン（フォロー・返信・リポスト・引用・いいね・リアクション）は鍵付きで押せる。押すと「〜できません」シート（「〈ドメイン〉をブロック中です」1 行＋［閉じる］［ブロックを解除…］）。プロフィールは「ブロック中のドメイン」バッジだけで、説明文やブロック解除ボタンは置かない。
- **4-2** 解除はその場の解除ダイアログ（設定画面と同じもの）。プロフィールの「…」メニューからも解除できる。
- **4-3** 「解除してフォロー」のような複合操作は提供しない。解除後に改めて操作する。
- **4-4** 解除ダイアログに［ミュートに変更］を並べる。
- **4-5** 他の Profile では制限がないことは示さない。

## 5. タイムライン・通知・検索

- **5-1** タイムラインには隠した痕跡を出さない（件数・プレースホルダとも出さない）。
- **5-2** 通知にも痕跡を出さず、未読数にも数えない。
- **5-3** 検索結果にも注記を出さない。
- **5-4** 受理済みのいいね・リアクション件数はそのまま表示し、注記しない。

## Misskey / X から学んだ「引き算」の要点

1. メニュー項目は「対象＋動詞」だけ（例: 「example.social をブロック」）。仕組みの説明はメニューにもボタン周りにも書かない。
2. 軽くて戻せる操作（ミュート、ミュート解除）は確認なしで即時実行し、「元に戻す」付きトーストで済ませる。
3. 確認ダイアログは「〜しますか？」のタイトルと 2〜3 個のボタンが基本。本文は判断に必要な事実（失うものの数など）に限り、1〜2 行まで。Misskey は「ブロックしますか？」の 1 行だけ。
4. 状態は文章ではなくボタン・バッジの見た目で示す（「ブロック中」のバッジ、鍵付きのボタン）。
5. ボタンの文言で伝わることを本文で繰り返さない（「この投稿だけ表示」があれば「表示しても設定は変わりません」は不要）。
6. 「変わらないこと」「起きないこと」「残るもの」は書かない。例外的な挙動の説明はヘルプへ。
7. 設定画面は一覧と最小の操作だけ。追加は「+」→ 小さなモーダル、空状態は 1 語。前置きの説明やバナーは置かない。
8. 入力の補助は確定時に 1 回だけ（入力中のプレビューや例示は出さない）。エラーは短く、入力欄の直下に出す。
