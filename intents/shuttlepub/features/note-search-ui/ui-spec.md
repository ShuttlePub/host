## 2. 画面と操作

### 検索欄
- 検索画面の上部に固定（sticky）。高さ 36px、プレースホルダは「検索」だけ。右端にクリア（×）ボタン（全条件と入力を消す）
- 欄は `role=combobox`（`aria-autocomplete=list`、候補の listbox を `aria-controls` で関連付け、選択中候補は `aria-activedescendant`）。外側の `role=search` で囲む
- Enter で検索する。キーワードだけ・投稿者だけ・両方のどれでも検索できる
- 検索画面に「＋投稿者」などの常設ボタンは置かない

### URL に保持する条件
- 確定した検索語と作者を URL に保持し、戻る操作と共有先で同じ検索条件を再現する（`d04-q16-search-url-state`）。
- 検索語がブラウザ履歴に残ることを許容する。`cursor` や途中結果は URL に含めない。

### `from:@acct` の自動変換と投稿者チップ
- 候補: `from:@` の後に入力すると、取得済みアカウントの候補を名前・acct の前方一致で最大 5 件出す（アバター・名前・`@user@host`、一致部分を強調）。候補は ShuttlePub が投稿を取得済みの作者のうち閲覧 Profile が公開参照可能なものだけで、ミュート・ブロック中の相手（個別・ドメイン）は出さない（`d04-q13-author-suggestion-scope`）。↑↓ で移動、Enter で選択、Esc で閉じる。mobile は各行 44px 以上
- 変換の契機: 候補を選ぶ・`from:@acct` の後にスペース・Enter。変換すると入力から `from:@acct` を取り除き、欄内に投稿者チップを出す
  - 変換だけでは検索しない（候補の選択・スペース）。Enter で変換した場合は、そのまま検索まで進む
- 変換の瞬間: チップを一瞬強調する（縮小からの出現＋アクセント色の外枠、約 1.4 秒で通常表示）
- 投稿者チップ: アバター（18px）＋ `@user`（アクセント色の薄い塗り、角丸）＋外すボタン ×。高さ desktop 26px／mobile 30px、× は desktop 24px／mobile 30px。acct が長いときは省略表示し、フル acct は title と読み上げで伝える（× の `aria-label` は「投稿者の指定を外す（名前）」）
- 外し方: チップの ×、またはキャレットが欄の先頭にあるときの Backspace。外した後は欄にフォーカスを戻す
- 投稿者は 1 人まで（d04-q02）。2 つ目の `from:` は前の投稿者を置き換える
- 欄の中の余白をクリックすると入力にフォーカスする

### 解決できない acct（U2=a）
- 未取得などで解決できない `from:@nobody@unknown.example` は、変換せず文字のまま欄に残す
- 欄の直下に赤字 1 行「@nobody@unknown.example が見つかりません」（`aria-invalid`、`aria-describedby` で関連付け）
- 検索はしない。リモートへの問い合わせ（照会）はしない（未取得のアカウントは取得済みの投稿もないため）
- 解決の根拠は自サーバーの確定 username か検証済みの remote acct 対応のみ（`d04-q14-acct-resolution-basis`）。表示用に導出しただけの acct では解決しないので、「見つかりません」になりうる。外部照会は同期・非同期とも一切しない
- host を省略した `from:@alice` は自サーバーの alice として扱う（`d04-q15-host-omitted-acct`）。API 契約は unit `note-search-author-lookup-api-contract`（resolve／suggestions の 2 operation）

### プロフィールからの入口
- プロフィールのヘッダー右「…」（［フォロー中］の右）で開くメニューの先頭に「この人の投稿を検索」。メニューは「この人の投稿を検索／リンクをコピー／@user をミュート／@user をブロック（赤）」
- desktop はボタン直下のドロップダウン（幅 248px）、mobile はボトムシート
- 押すと検索画面へ移り、その人の投稿者チップが入った状態で、開いた時点で検索する（投稿者だけの検索、新しい順）。欄にフォーカスし、続けてキーワードを足せる。これは `d04-q18-profile-entry-immediate-search` で確認した決定で、キーワード入力待ちにはしない

### 検索結果
- 新しい順。v6 の投稿カードをそのまま使う（リアクションのチップ・アクション行も同じ）
- 一致語を強調する（U4=a、`mark` 要素、アクセント色の薄い塗り）
- CW 付きは畳んだまま。CW 文に一致した語は強調する。本文の一致は「もっと見る」で開くと見える（「本文に一致」等の印は出さない）
- 他サーバーのアイコン・絵文字画像は `d09-q06-remote-media-fetch-path` に従う。安全な自サーバー経由の配信経路がなければアイコンを代替表示し、絵文字は `:name:` 表示にする。ブラウザから外部サーバーへ直接画像を読み込まず、安全な配信（プロキシ）は別 unit とする
- 返信は名前行の下に「返信先 @user@host」
- コメント付き引用は本文の下に引用カード（引用元のアバター・名前・acct・本文）。引用元の本文は一致の強調対象にしない
- 純粋なリポストは出さない（q07。プロフィールのタイムラインには「○○がリポスト」として出る）
- 件数は表示しない

### 次ページ（U3=b）
- 末尾までスクロールすると次のページを自動で読み込む。読み込み中は末尾に投稿型のスケルトン
- 読み込みに失敗したときだけ、末尾に「読み込めませんでした」＋［再試行］
- 全件を出し切ったら何も出さない
- 時間上限で `truncated=true` の途中結果になった場合は、返された非空 `next_cursor` で手動再開する［途中から続きを読む］を表示する。自動読み込みは停止したままにする（`d04-q17-timeout-resume`、API 契約 #23）

## 4. モックで仮に決め、v2 合意に含めたこと
- 変換の契機: `from:@acct` の後のスペース・Enter・候補の選択。変換だけでは検索せず、Enter で変換した場合は検索まで進む。プロフィールから来たときは開いた時点で検索する
- 投稿者の数: 1 人（d04-q02）。2 つ目の `from:` は置き換え
- 文言: プレースホルダは「検索」のみ。件数・説明文・空状態の案内は出さない（0 件は「見つかりませんでした」だけ）

## 5. D09 差分 UI（他サーバーのカスタム絵文字リアクション）

D04 モックの中で、ホームと検索結果の Leo（misskey.example）の投稿に示した。grill 記録は [D09 candidate](../../packets/candidates.md#d09)。

- **地球マーク（U5=c、`d09-q04-emoji-origin-indicator`）**: 他サーバーのカスタム絵文字のチップは、絵文字の直後・件数の前に小さな地球マーク（11px、muted 色）を出す。同名の自サーバー絵文字（例: `:kusa:`）のチップと並んでも区別できる。読み上げは「:name:（host） でリアクション（件数）」
- **外部絵文字は既存チップへの便乗のみ（`d09-q01-existing-reaction-chip-only`）**: 投稿に付いている既存リアクションのチップを押したときだけ使える。最近使った絵文字・ピッカー・ピッカー検索には出さない。操作は D03 C3 と同じ（未反応のときだけ、他人のチップで同じ絵文字のリアクションになる）
- **画像を表示できない場合（`d09-q02-unavailable-emoji-name-fallback`）**: 画像の代わりに `:name:` の文字をチップに出し、押せる（送信できる）
- **元サーバーで削除済みの絵文字（`d09-q03-expire-deleted-emoji-cache`）**: こちらの保存分を一定期間後に削除し、以後は取得失敗と同じ `:name:` の見た目で、同じく押せる（見た目と押せることは v1 モック提示に異論がなかったことによる補完。具体的な期間は未決）

## 6. 実装上の注意
1. **変換の判定は欄の入力イベントごと**に行う。`from:@` の後の入力中は候補を出し、確定の契機（スペース・Enter・候補の選択）で投稿者を確定する。候補の選択は候補の `actor_url` で確定し（acct を再度 resolve しない。候補に出る remote の acct は表示用で未検証でありうる、`d04-q14-acct-resolution-basis`・`d04-q13-author-suggestion-scope`）、手入力した `@user@host` の確定時だけ acct を resolve する（`resolveNoteSearchAuthor`）。解決できない場合は文字を残してエラー行を出し、検索 API を呼ばない。
2. **候補の選択（クリック・Enter）は変換のみ**で検索しない。候補なしの Enter 変換は検索まで進む。この違いを実装で崩さない。
3. **フォーカスを失わせない**: 変換後・チップを外した後・クリア後は欄にフォーカスを戻す。プロフィールから来たときも欄にフォーカスする。メニュー／ボトムシートは Esc で閉じ、「…」ボタンにフォーカスを戻す。
4. **自動読み込みは中断・失敗で止める**: 時間上限で中断した結果、または次ページの失敗表示中は、スクロールしても自動で次を読まない（失敗時は［再試行］だけで読み直す）。
5. **検索条件は投稿者（解決済みの actor）とキーワードを別に持つ**。投稿者を表す文字列（`from:@…`）をキーワードとして API に渡さない。
6. **クラス名の衝突に注意**: v6 の `.menu`（ヘッダーの Profile メニュー用、top 固定）を流用するとプロフィールの「…」メニューの位置がずれるため、モックは `.prof-menu` で上書きした。実装では部品ごとにスコープを分ける。
